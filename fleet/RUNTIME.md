**13 of 98 sites audited in a browser.** Everything below was
measured by loading pages and clicking, not by reading source.

| measure | total | meaning |
|---|---:|---|
| routes reached | 56 | discovered by following in-app links |
| crashed or threw | 0 | an error boundary rendered, or an uncaught error |
| routes with no `<h1>` | 31 | no page title in the route's default state |
| dead-end lists | 12 | a populated table whose rows link nowhere |
| unmarked tab groups | 49 | the active tab is invisible to the accessibility tree |
| inert controls | 35 of 267 clicked | 87% responded |

A toast is not counted as a response: a handler whose only effect is a success message is
the defect, not the reaction to it.

**6 site(s) expose no in-app links at all** — navigation is entirely click
handlers on buttons. An agent reading the accessibility tree cannot discover their routes,
deep-link into one, or open one in a new tab. It also means this crawl, which follows
links, saw only their entry page: their route counts below are a floor, not a census.
